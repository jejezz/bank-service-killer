## 완료한 단계 기록: 서비스 단위로 모드 만들기 + 검색

**상태: 구현 완료** (서비스 지정이 카테고리보다 우선, v4 저장 형식, 서비스별 탭의 검색·거르기·한꺼번에 정하기, 모드 복제, 메인 목록 검색).

### 배경 (실사이트에서 확인한 것)

사이트가 요구하는 보안 서비스는 보통 **몇 개뿐**이에요. 예를 들어 한 사이트의 필수 목록은
VeraPort(통합설치), AnySign(공동인증), TouchEn nxFirewall(방화벽), TouchEn nxKey(키보드 보안) 네 개였어요.

- 개발 모드에서 이 사이트에 들어가면 "필수 프로그램 설치" 화면이 떠요.
- 뱅킹 모드에서는 그 화면이 뜨지 않아요. (확인됨)

카테고리 단위로만 모드를 정의하면 카테고리 안의 서비스를 전부 켜게 되어, 사이트가 요구하지 않는 서비스까지 켜져요.
서비스 이름으로 직접 골라 모드를 만들면 사이트별로 필요한 서비스만 켜는 작은 모드를 만들 수 있고, 전환도 빨라져요.

### 요구사항

1. **서비스 단위 선택**: 모드를 만들 때 카테고리뿐 아니라 서비스를 하나씩 골라 켜기 / 그대로 / 끄기를 정할 수 있어요.
   - 서비스를 직접 정한 값이 카테고리로 정한 값보다 **우선**해요 (예: 카테고리는 켜기인데 서비스 하나만 끄기).
   - 카테고리와 서비스를 섞어 쓸 수 있어요.
2. **검색과 거르기**: 등록된 서비스가 많아져도 고르기 쉽도록 모드 편집 창(서비스 목록)에 검색 상자를 둬요.
   - 서비스 이름·표시 이름·메모·카테고리로 검색해요.
   - 거르기: 이 PC에 설치됨 / 실행 중 / 카테고리 / 드라이버 연동.
   - 선택한 것만 보기, 보이는 것 모두 선택·해제.
3. **메인 화면 목록에도 검색 상자**: 감시 목록이 길어졌을 때 이름으로 바로 찾아요.
4. **미리보기와 현재 모드 판정은 그대로 동작**: 서비스 단위 지정이 있어도 `planFor`(계획)와 `detect`(현재 모드 판정)가 같은 규칙으로 계산해야 해요.

### 설계 메모

- **데이터**: `WatchMode`에 서비스별 지정을 더해요. 예: `services: { "<서비스 이름>": "on" | "keep" | "off" }`.
  `watchlist.json`은 v4로 올리고, v3은 서비스 지정 없이 읽어 그대로 동작하게 해요 (마이그레이션 테스트 필요).
- **규칙**: `wantFor(mode, item)`을 `서비스 지정 → 카테고리 on → 카테고리 keep → 끄기` 순으로 바꿔요. 이 한 곳만 고치면 계획·판정·미리보기가 함께 따라가요.
- **카테고리 이름 변경·삭제, 서비스 이름 변경·삭제**가 서비스 지정을 깨뜨리지 않게 함께 갱신해요 (이미 카테고리에는 같은 처리가 있어요).
- **편집 화면**: 모드 편집 창을 "카테고리별 / 서비스별" 두 탭으로 나눠요. 서비스별 탭은 서비스마다 켜기·그대로·끄기 세그먼트와 검색·거르기를 둬요.
  카테고리로 정해진 값은 흐리게 "카테고리: 켜기"로 보여 주고, 서비스 지정이 이를 덮어쓰면 표시해요.
- **복제**: 기존 모드를 복제해 사이트별 모드를 빨리 만들어요 (예: "뱅킹" 복제 → "○○은행"). 서비스가 몇 개뿐인 작은 모드를 쉽게 만들기 위해 필요해요.
- **성능**: 서비스가 수백 개까지 늘어도 검색이 즉시 반응하도록 목록은 지연 생성(`ListView.builder`)으로 그려요.

### 이어서 생각할 것 (이 단계 밖)

- **사이트별 프리셋**: 카탈로그에 "이 사이트는 이 제품들이 필요해요"(예: `sites`) 항목을 두고, 사용자가 사이트 이름으로 모드를 한 번에 만들 수 있게 해요.
  위 화면처럼 사이트가 알려 주는 필수 목록(VeraPort, AnySign, nxFirewall, nxKey)이 카탈로그 제품과 바로 맞물려요.
- **제품 단위 선택**: 한 제품이 서비스 여러 개로 설치될 때(예: INNORIX EX Management + Service) 제품 하나로 묶어 고르게 해요.

### 완료 기준

- 서비스 이름으로 고른 모드를 만들고 저장하면, 전환 미리보기와 현재 모드 판정이 그 선택대로 동작한다.
- 서비스 지정이 카테고리 지정보다 우선한다 (단위 테스트).
- v3 `watchlist.json`을 읽어도 동작이 바뀌지 않는다 (마이그레이션 테스트).
- 서비스가 200개 이상이어도 검색 입력에 즉시 반응한다.

## 보류 (필요해지면)

- **README 갱신**: 모드·카탈로그·첫 실행 설명과 스크린샷·데모 GIF (`tool/readme/capture.sh`). 정식 릴리스 전에 필요해요.
- **프리릴리스 먼저**: `0.2.0-rc.1` 태그로 먼저 내고 써 본 뒤 `0.2.0`으로 가요.
- **서비스별 메모리·CPU 표시**: 서비스 PID로 메모리는 쉽게 얻어요. CPU는 두 번 재서 차이를 구해야 하고, 드라이버는 프로세스가 아니라 보이지 않아요. 모드 전환 전후 메모리 차이를 로그에 남기는 것부터 해요.
- **명령줄 `--mode <이름>`**: 바탕화면 바로가기로 모드를 바꿔요.
- **서명 키 백업**: 공개키를 두 개(주 키·백업 키) 받아들여, 주 키를 잃어도 앱을 다시 배포하지 않게 해요. 큐레이터가 늘면 GitHub Actions 서명으로 옮기는 것도 검토해요.
- **카탈로그 채우기**: 사용자 신고(GitHub 이슈, `catalog` 라벨)를 확인해 `catalog/catalog.json`에 반영하고 `version`을 올려 서명해요.
- **설치 프로그램 코드 서명**: SmartScreen 경고를 줄이려면 필요해요.
- **릴리스 워크플로에 테스트·분석 단계 추가**: 지금은 빌드만 해요.
